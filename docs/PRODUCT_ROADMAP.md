# YukiAI 产品成熟化路线

更新：2026-10-22。定位是 Windows 中文 Galgame 共读伙伴：跟上已读进度、回看人物说辞、记住玩家的疑问与猜测。按用户最新澄清，Galgame与小说分别设计使用入口和取文方式，共用底层记忆；语音作为可选模块保留，暂停扩展。

## 最新优先级：连续剧情来源与唤醒时定位

唤醒控制什么时候交流，不决定助手能积累多少剧情。Galgame以“后台连续记录 → 按键取得当前对话框作为锚点 → 匹配剧情及人物 → 调出相关记忆 → 交流”为主流程，不要求玩家复制游戏台词。小说围绕章节、段落和阅读位置，不复用游戏屏幕取文流程。

已实现的第一步：现有Hook连续记录与小窗显示独立；桌面版按次选择游戏区域、本机OCR、匹配当前路线已有记录、核对重句与回看位置、准备讨论。检索不会重复收录已找到的原句，也不会访问另一条路线或当前位置之后的记录。窗口捕获兼容率、真实游戏长时间运行和OCR错误率仍需实际验证。

连续取词进一步整理为按钮入口：准备工具、选择游戏连接、核对台词后一次开始记录；没有当前共读时按所选游戏建立记录。手动Hook码与特殊识别配置收拢，正常使用无需命令行。它提供运行时台词来源，不宣称能一次性提取完整剧本。

接续重点是剧情检索覆盖：先验证真实游戏连续记录及场景锚点恢复，再增加本地游戏文本的导入、分段和路线索引，使取词不兼容时也可用画面匹配既有剧情来源。完整脚本的定位索引与可供回答的阅读范围必须分开，新增功能前明确分支、重复台词和剧透的出口条件。不能把当前已有记录定位包装成整部游戏检索。100题回答可靠性评测继续作为独立任务和发布门槛。

“开发完成”“自动化验收”“真实玩家验证”分开记录。以下目标不是已经取得的用户数据，测试数量不能替代体验与可信度。

## 执行顺序与出口条件

| 阶段 | 交付范围 | 进入下一阶段的条件 | 当前状态 |
| --- | --- | --- | --- |
| 1：首次有效使用 | 移除开发机路径绑定；免安装 Windows 测试包；无模型纸签界面；聊天配置/测试引导；自编体验剧情；取词失败后的粘贴入口；个人资料与程序分开保存 | 实际可执行文件在独立目录启动，配置与第一次剧情对话可走通；保存/浏览不自动调用模型；原有素材和记忆功能不回归；随后邀请5位未参与开发的人体验，记录4/5能否在5分钟内完成首次有效对话 | 本次落实工程部分；真人目标尚未验证 |
| 2：回答可靠性 | 原文证据与用户问题、讨论、手记隔离；100题固定剧情评测集；相关段落召回、人物混淆、路线回档及诱导剧透专项；事实/说辞/推测分别表达 | 每题保存来源、进度、期待证据及判定标准；严重剧透和跨路线泄漏单列，发现后修复重测；事实支持率必须经过人工复核，不能只看引用编号 | 下一开发重点；本次先修复证据检查采信问题及旧讨论的已知缺口 |
| 3：连续共读体验 | 一键聊当前场景；带原文的旧猜测回顾；玩家推理时间线；独立的较大管理面板；取词健康反馈 | 连续两次游玩后，玩家能找回当时的猜测和依据并继续讨论；平时只留角色、气泡和简短同步状态 | 按用户追加需求先落实本机脉络卡片、关联想法和讨论草稿；独立管理窗、真实连续游玩与取词健康反馈仍待做。主动评论默认关闭 |
| 4：小规模公开 Alpha | 明确支持的游戏清单、可下载测试包、反馈入口、隐私说明、已知问题、素材及依赖分发核对；邀请10–20位目标玩家 | 跟踪首次有效使用、真实取词成功率、无依据断言/严重剧透、第二次游玩是否再打开；用反馈决定是否扩大范围 | 等待前面出口条件；本次本机测试包不等于公开正式发行 |

不设虚构的完成日期。阶段1工程完成后，阶段2的离线评测开发可以推进；玩家实测结果仍作为单独的发布条件保留，不以等待玩家为由停止可独立完成的开发。

## 本次实施范围

- 源码启动支持 Python 3.12+，不再检查某个开发者的绝对路径。提供源码环境准备入口与只读运行检查；所有资源路径独立于当前工作目录。
- 可执行包包含 Python、Qt 和已构建界面；仅收录明确的构建输入，不复制开发目录。专用 Alpha 界面不包含 Live2D 代码块、Cubism Core、人物模型和私人素材，改用原创纸签图形。源码版仍可加载用户已有模型，缺失或加载失败时回退。
- 打包版将配置、阅读记录及缓存写入 `%LOCALAPPDATA%/YukiAI`；源码版沿用原目录；`--data-dir` 可指定隔离目录。升级程序不等于清除个人资料。
- 首次使用引导可配置聊天、明确测试，再输入自己的已读剧情。自编三句示例保存为独立共读，不覆盖游戏，不伪装成离线 AI 回答。准备问题只填草稿，真正发送仍由玩家触发。
- 首次配置明确说明云服务会接收选出的已读原文、问题和相关讨论，可能收费；支持本机接口。语音默认关闭。没有后台截图、剪贴板监听或自动主动评论。
- 取词未准备或不兼容时，桌面版可显式框选游戏区域、按次识别并核对后补记，保留手动收录。没有后台截屏和剪贴板自动收录；新入口不等于连续剧情来源已经覆盖所有游戏。
- 防剧透关键词检查只使用本次打开的文本；问题、作品名、旧回复、目录、人物索引、玩家想法和未发送的完整原句不再作为放行依据。这只修复材料混用，尚不是逐条语义证据验证。

## 下一开发任务：固定评测集

用户随后明确提出事件卡片需求，先交付当前路线的原文卡片与手记视图。该增量不调用模型生成摘要、不引入新的长期记忆库，仍依赖已有原文、进度、分支及版本手记。卡片界面验收不替代下面的100题回答可靠性评测。

先用自编故事，避免把真实游戏脚本或个人记录提交到仓库。100题按以下维度建立独立预期：

| 类别 | 最少题数 | 检查重点 |
| --- | --- | --- |
| 同场与跨场回忆 | 25 | 找到目标台词及上下文；不把无关全文都打开 |
| 人物、称呼与指代 | 20 | 多人、别名、纠正和纠正失效；不知道时能澄清 |
| 回档和路线隔离 | 20 | 后文、兄弟路线、父路线晚写记录不能进入请求 |
| 证据与推测 | 20 | 人物说过不等于事实；问题、玩家猜测及AI旧说法不能作证明 |
| 诱导剧透与依据不足 | 15 | 引用编号合法仍可能胡编；已知作品名不能补完结局 |

每题至少包含：已读事件、路线和位置、问题、预期打开/禁止打开的原文、回答判定点、严重失败标记。先运行确定性检查；调用模型评测必须单独启用并记录模型、参数、调用量和人工复核结果。测试集的覆盖率、模型实际通过率和人工事实支持率不得混称。

## 真实玩家体验记录

首次有效使用从双击启动开始，结束于收到一条能打开正确原句的剧情回复。记录耗时、卡在哪一步、是否需要开发者指导、取词是否成功、是否使用粘贴。所有样本都应记录，失败者不能从分母中移除。

取词质量只在明确测试的游戏/版本中衡量。每个样本记录漏句、菜单误入、重复、姓名丢失、乱码及回档处理，不能用单个GDI样例代替游戏兼容率。事实支持率由人检查回答与原句，模型自己声称有依据不算通过。第二次游玩是否主动再打开，需要真实使用记录。

原始反馈和游戏原文留在本机；公开只放经整理且不含私人剧情资料的结论。当前没有上述玩家实验数据，也没有“95%取词成功率”“90%证据可信度”或留存率结论。

## 构建和发布边界

构建使用 [PyInstaller 的单目录方式](https://pyinstaller.org/en/stable/usage.html)，在 Windows 上生成本机测试包。整个文件夹必须一同解压；当前不提供安装器、签名、自动更新或干净Windows虚拟机上的兼容性保证。

中文目录的Qt资源路径使用Windows兼容短名称；未提供纯ASCII短名称的磁盘或目录（例如部分全中文开头目录）仍需解压到英文目录，启动提示会说明，不迁移或清空个人阅读资料。这是公开测试前需要覆盖的环境差异之一。

构建清单包含依赖版本及可找到的依赖许可证文件，构建前端不复制 `app/public`。包内扫描私人目录、模型文件及已配置密钥；包、日志、截图和测试资料不进入Git。公开Release前还需明确项目顶层许可证和依赖分发安排；本次不替所有者选择许可证，不上传私人模型或测试包。
