# Yuki 系统说明

Yuki 是一个贴在屏幕上的共读伙伴。它陪人读已经看过的 Galgame 台词或小说段落：聊感受、对情节、分清人物说辞和叙述，并在问到典故时解释。它不检索攻略，不操作游戏，也不把还没读到的内容当成已知剧情。

这份说明对应仓库里的当前源码。模型、密钥、聊天记录和剧情数据库不在仓库中。

## 1. 它解决什么问题

普通搜索和直接问通用模型，用的是整部作品的介绍、攻略和训练记忆。Yuki 用的是你这条阅读进度里已经确认读过的原文。

因此它适合这些问题：

- 刚才这一段在说什么。
- 这句话里的典故指什么。
- 到目前为止，这个人说过什么，叙述里又写了什么。
- 我回到前面的进度了，按现在这段重新聊。

它不适合这些问题：

- 真结局怎么达成，选哪句，后面谁会死。
- 还没收录的章节里发生了什么。

## 2. 两种阅读

建立共读时选择一种。选择写在 `runs.mode`，默认 `galgame`。

| | Galgame | 小说 |
| --- | --- | --- |
| 进度单位 | 路线、书签、分支、回档 | 章节和已读段落。界面仍保留书签，用来停在某一句 |
| 如何认人 | `美咲：台词`、`【美咲】台词` | 同上，另外认识 `孔乙己说道，“……”` |
| 如何分段 | 选项、时间地点转换，或满 40 句 | 再加 `第一章`、`第X回` 这类标题 |
| 提问语气 | 不谈选项后果 | 不谈路线、选项和攻略，也不许用书名补后文 |

`他/她/我/你` 开头的“说道”不会被当成角色名。

## 3. 一次提问怎么发生

界面把问题和当前 `epoch` 发给本机 `POST /api/chat`。服务只在本机 `127.0.0.1` 上。

1. 用 `epoch` 确认阅读进度没有在提问期间被换掉。
2. 若当前没有共读，就走普通聊天：最近对话加角色设定。
3. 若正在共读，只从当前路线、当前位置以前的原文里取材。
4. 材料打成一份 JSON，连同模式对应的系统提示，发给设置里的 OpenAI 兼容接口。
5. 回复必须是一个 JSON 对象，含 `text`、`emotion`、`answer_type`、`evidence_ids`。
6. 引用编号必须来自这次打开的句子。分析类回答不能没有编号。
7. 若回复里出现材料中没有的结局、真实身份或选项后果，相关句子会被删掉；整句都站不住时，改成不确定并清空依据。
8. 通过之后才写入本地记录。界面上的「依据」打开的是本机保存的全文，不是送给模型的截断文本。

模型若没按 JSON 返回，会先从文本里抽出 `{...}`。仍然失败就再请求一次。两次都不行，界面得到一条不含上游正文的错误。

普通聊天和共读讨论是分开的。共读不会把另一条路线的聊天带进来。

## 4. 记忆如何节省上下文

原文一直完整留在本机 SQLite。送给模型的只有一小部分。

分段规则在 `scripts/yuki_story.py`：

- 一场最多 40 句。选项、章节标题，或旁白开头的“第二天 / 与此同时 / 【场景】”会另起一段。
- 先打开问题对上的那一段。若它不是当前结尾，当前进度只再留最后 4 句，用来标明人读到哪里。
- 正在读的短段（不超过 12 句）整段打开。更长时打开结尾 8 句、开头的旁白，以及问题点名的那一句和它前后各 2 句。
- 更早的段落最多再打开 2 段，而且必须和问题对得上。只因为共享一个两字片段而分数差很多的段落不会打开。
- 送给模型的材料里写明确认进度，以及这一问问的是第几句。问得更早只表示在回顾，不把进度改到那里。
- 问题会切成 2、3、4 字。较长的词权重大，用来压过“的灯”这类常见两字。
- 单句送给模型时大约不超过 160 字，并尽量留住问题里的词。全文仍在数据库里。
- 打开的原文预算大约 2400 字。放不下时优先留下点名的句子和当前结尾。
- 没打开的段落只留目录：范围、在场的人、开头一句短摘录。目录最多 8 条。
- 最近讨论只带 6 句，每句大约 180 字。
- 人物索引里，已经打开的句子只留编号，避免同一句台词送两次。没打开的说辞才附上短文本，而且不能当作引用编号。

人物卡把两类分开：

- `claims`：这个人自己说的。
- `witnessed`：叙述里提到这个人。

说辞不会被改写成事实。

## 5. 进度、分支和回档

当前可用原文 = 当前作品的这一次阅读 + 当前分支祖先链上、阅读位置以前的已确认事件。

不能用“这个人历史上读过的全部句子”。回到书签之后，书签后面的句子，包括另一条分支里的句子，都不会进入提问、目录、人物卡或讨论。

阅读位置要经过连续核对，不能凭一句重复台词就改：

- 取到一句和较早原文相同、并且足够长的台词时，先记住，不写入。下一句若正好是它后面的那句，才判定回到了旧进度，暂停记录，并请你回书签。下一句对不上，就只把后一句当新台词。
- 一次粘贴若从某一句起连续两句都和已读原文相同，会拒绝写成新进度。
- 连续两问都落在比确认进度早至少 12 句的同一处，剧情记录和回复下方都会写明“最近两问都在看第 N 句附近”，但进度数字不动。回顾不是读档。小说回复不会把这段叫成“路线”。

这些动作会增加 `epoch`，并取消还没回来的回复和朗读：换一篇共读、回档、改阅读位置、切换分支、新开一段讨论。向前继续收录通常不取消正在进行的、针对旧进度的合理回复；若回复回来时进度已经对不上，它不会被保存。

在回退位置继续收录新文本时，会另存一条分支，旧分支保留。

小说的默认分支名叫「正文」。Galgame 的默认分支名叫「共同线」。

## 6. 取词

Galgame 可以用本机的 Textractor 取当前窗口里的新台词。流程在 `scripts/yuki_capture.py`。

- 先选游戏进程，再选和画面正文一致的来源。菜单、单独跳出的姓名不要选进正文。整行就是「保存」「读取」「F5」这类界面文字时，预览里还能看到，但不会写入正文。短的对白，例如「知道了」，仍会保留。
- 开始记录之后才写入。预览里的旧句不会补录。
- 大约 1.5 秒内的连续重复会丢掉。逐字增长的同一句会合成一句。不同场景的正常重复会保留。
- 取词本身不调用模型，也不合成语音。
- 回档、换共读、换路线、来源过多、单条过长或取词过快，都会暂停写入。
- 它不能发现游戏自己已经读档。读档前要先暂停，回到对应书签，再重新开始记录。

小说目前以手动收录为主。每次最多 200 行、每行 2000 字。

## 7. 界面和桌面窗口

`app/src/` 是小窗页面。`scripts/yuki_window.py` 用本机 Qt 打开透明窗口，默认 320×460，最小 280×380。启动后先只显示一个可拖动的 Yuki 按钮；点击或按 Ctrl+Alt+Y 打开或收起小窗。收起时本机服务、阅读记录和取词继续运行。右键按钮可以退出。

页面上能做的事：

- 拖动角色附近的操作栏移动窗口。平时操作栏隐藏。
- 一条浅色气泡。短回复随文字变窄，长回复先显示三行。
- 点「聊聊」才输入。回想、新聊和收起在「···」里。
- 设置里填写聊天和语音。密钥只留在本机，接口不把密钥送回浏览器。
- 语音默认关闭。可以试听，或让它朗读当前中文回复。
- 「剧情记录」里收录原文、书签、路线，以及「目前记得」。
- 共读回复若依据不足，气泡下方会说明，回想里标「没把握」。

没有麦克风、摄像头、读屏或代替玩家操作游戏的功能。

## 8. 本机文件

| 路径 | 作用 | 是否进仓库 |
| --- | --- | --- |
| `app/src/`、`scripts/yuki_*.py` | 界面和本机服务 | 是 |
| `app/vendor/live2d/` | Cubism Framework 源码和许可 | 是，不含 Core 运行库 |
| `app/dist/`、`app/public/model/` | 构建结果和模型 | 否 |
| `.yuki.local.json`、`.env.local` | 接口地址、模型和密钥 | 否 |
| `data/story.sqlite3` | 原文、进度、书签、共读讨论 | 否 |
| `chat_history/` | 未进入共读时的普通聊天 | 否 |
| `tools/textractor/` | 取词程序 | 否 |

启动：双击 `start_yuki.cmd`，或用 myenv 的 Python 运行 `start_yuki.py`。默认端口 12393。`--mode preview` 不调用外部接口。`--headless` 只开本机页面。

前端改动后要在 `app/` 里执行 `npm run build`。服务读取的是 `app/dist`。

聊天接口是 OpenAI 兼容的 `/chat/completions`。当前本机示例是 Command Code 的 `https://api.commandcode.ai/provider/v1`，模型名形如 `deepseek/deepseek-v4.1-flash`。DeepSeek 请求会关掉额外的思考字段，减少不按 JSON 返回的情况。语音可以是 Fish Audio 或另一路 OpenAI 兼容合成，默认关闭。

## 9. 主要接口

全部只接受本机来源。

- `GET /api/status`、`GET/POST /api/settings`、测试聊天和测试语音。
- `POST /api/chat`、`POST /api/speech`。
- `GET /api/story`，以及建立、切换、收录、书签、回档、进度、分支、新讨论。
- `GET/POST /api/capture/...`：进程、连接、选来源、开始、暂停、断开、手动 Hook 码。

收录接口要求明确勾选“这些内容我已经读过”。

## 10. 检查

```text
python -m unittest scripts.test_window_backend scripts.test_window_settings scripts.test_story_memory scripts.test_capture
python scripts/audit_upload.py
```

`scripts/test_story_memory.py` 用自编故事和短章节检查：一百句收录、重复句、重启、回档、嵌套分支、迟到回复、当前场景中被问到的句子、无关段落保持关闭、超长句只截取关键词附近、小说未读章节不进入提问、越界剧透降级，以及实际发给模型的上下文不含另一条路线。

`scripts/verify_story.cjs` 在 320×460 和更小的窗口里检查收录、书签、依据和回档。它使用本地回复替身，不调用云接口。

推送前运行 `scripts/audit_upload.py`。它核对允许上传的源码名单，并检查暂存内容里有没有已配置的密钥。失败时不要用 `git add -f` 把排除文件推进去。规则写在 `docs/PUBLISHING.md`。

## 11. 已知边界

- 热门作品仍可能被模型用另一种说法讲出后文。现在会拦截“真结局”“真实身份是某某”“选 A 会”这类明确说法，挡不住换一种说法。
- 最近一段里有好几个人说话时，“她”或“他”只能暂定成最后开口的那一位，回答要先说明指的是谁。只有一个人时，会按这个人打开较早的原文。
- 取词不能自动发现游戏读档，也不能保证每一款游戏的 Hook 都正确。
- 「目前记得」展示最近四段，以及最近说过话的十二个人。更早的内容要提问才会打开。
- 整理目录和人物索引不调用模型，所以它不会自己写出一段文学性的长摘要。
- 确定性测试能保证另一条路线的原文没有送进本次请求。它不能证明模型的训练记忆绝不泄漏。
