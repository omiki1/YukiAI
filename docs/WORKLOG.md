# 2026-10-19 工作记录

这一天把 Yuki 从「贴在游戏旁边的聊天窗」推进到能按已读原文共读。系统现在怎么工作，见 `docs/SYSTEM.md`。这里只记这几轮实际做了什么、测了什么、还留着什么。密钥和小说全文都没有放进仓库。

## 共读记忆

`e2fa9b3` 起，提问不再只带最近 4 句。当前路线会整理场景摘录，并把人物原话和旁白提及分开。回档后，另一条线的句子进不了提问。回答里如果出现材料中没有的结局、真实身份或选项后果，会改成不确定。

`869aa45` 改成按剧情块加载。问到的内容整段打开，对不上的场次只留目录。

`d26bb2d` 收紧上下文。长场景只打开对得上的那一句和前后文，超长单句只截关键词附近送给模型，全文仍留在本机。未打开的场次是短目录。最近讨论只留六句。

`4c10f08` 补上一个漏洞：正在读的这场如果很长，问到中间那句时，以前只看得到开头和结尾。现在会打开那一句和前后文，结尾也还在。人物列表改成最近说过话的人优先。

`4aafa3b` 让三四字的词压过「的灯」这类两字碎片，避免为了一个常见两字打开整段无关剧情。模型如果没按 JSON 返回，先从正文里抽出对象，还不行再请求一次。引用了没打开的原文则直接失败，不再用同一次提问打第二遍。

## 小说和指代

`da5cf5f` 增加小说模式。建立共读时可选 Galgame 或小说。小说按「第一章」这类标题切开，认识「某某说道」。未读章节不进入提问，提示里也不谈路线和选项。

`41227d7` 处理问句里只有「她」或「他」、没有人名的情况。从最近一段有对白的场次往回找。那段只有一个人，就按这个人打开更早的原文。有好几个人时，只暂定最后开口的那位，并要求回答先说明指的是谁。「其他」不会被当成「他」。问句里已经有名字，就以名字为准。

`82f9c99` 补小说。叙述里的冒号不再被当成人物名。几乎没有对白时，用已读文字里明显反复出现的人名当作「他」或「她」。问长相时，会额外打开写到脸、眼、眉、身材的句子。分不出先后，就不当成确定指代。

指代还没有完全消掉。最近几个人同时在场，而「她」不是最后说话的那个，仍可能指错。只被提到一两次的人，也不会被当成叙述里的主角。

## 进度核对

`e7e1aab` 规定进度不能凭一次信号就改。

- 取到一句足够长、又和较早原文相同的台词，先记住，不写入。下一句若正好是它后面那句，才暂停记录，并提示回书签。
- 一次粘贴如果从某一句起连续两句都和已读原文相同，拒绝写成新进度。
- 连续两问都落在比确认进度早至少 12 句的同一处，界面写明是在回顾。进度数字不动。
- 「知道了」这种短句不触发回溯。

`01f61dc` 把「最近两问都在看第 N 句附近」同时放到剧情记录和回复下方。小说回复不再把阅读叫成路线。进度说明可以在窄标题里换行。

## 取词

`f4055e6` 整行如果只是「保存」「读取」「设定」「跳过」「标题」「快进」，或 `LOAD`、`Config`、`F5`、纯数字，预览里看得到，但不写入正文。句子里提到「保存这封信」仍会留下。

用一百句混合样例测过：80 句正文都进了记录，夹在中间的菜单没有进。把开头两句再放一遍，记录暂停，进度停在第 80 句。这还不是某一款商业游戏的实测。

## 小说试读

下载了老舍《骆驼祥子》第一章做本地试读，正文没有提交。只读到第一章结尾「希望多半落空」，没有放入第二章。

- 「他」对上祥子。
- 「他为什么非要自己的车」引用了车份儿，以及把买车那天当成生日。
- 「他长什么样」引用了圆眼、肉鼻子、短粗眉，和颧骨到右耳那块被驴啃过的疤。
- 「后来他的车被兵抢走了吗」没有确认，只指出最后一句在埋伏笔。

响应速度这一轮没有改。晚上的 Galgame 实测也还没用真实游戏文本对过约一百句。
