# Yuki · 一起看剧情的朋友

一个正在开发的 Galgame 共读伙伴。用户主要在玩galgame时：一起交流感受、分析剧情和伏笔、梳理人物动机与关系；遇到其他国家文化、历史、文学典故时结合上下文讨论。默认跟随已读进度，不剧透。

## 当前进度

- 独立的透明桌面小窗，默认320×460，最小280×380；角色随窗口一起缩小。
- 操作栏位于模型头顶附近，平时隐藏；鼠标移到角色可见部分时显示，移向按钮时保留，离开后收起。可拖动“Yuki”移动窗口，键盘 Tab 也能打开操作栏。设置等面板打开期间，操作栏暂时保留在窗口顶端。
- 单条聊天气泡，短回复随文字缩窄，长回复默认最多三行，点击“展开”查看全文。
- 默认使用像素复古界面；在“设置 → 外观 → 界面主题”可切换像素、磨砂玻璃、纸本、霓虹和经典五种外观。选择会在本机记住，更新不覆盖已有主题偏好。像素字体随应用提供，标题和按钮使用点阵字，剧情正文与回复保持普通字体。
- 点“聊聊”才打开输入框，发送时收起；“···”中提供回想、新聊和收起气泡。回复不会自动抢走输入焦点。
- 中文文字聊天、逐字显示、当前对话回想和本地记录。
- 接入本地提供的 Live2D 模型，保留表情、眨眼和固定头身；默认缩小至此前的85%，可用滑杆调整60%～110%。
- 模型上方的设置中可配置聊天与语音服务；支持 OpenAI 兼容 LLM、OpenAI 兼容 TTS 及 Fish Audio。保存后立即生效。
- 语音默认关闭，可手动试听或开启自动朗读当前中文回复。没有麦克风、摄像头、读屏或游戏操作功能。
- 对话框可收起为“Yuki · 聊两句”，草稿和回复会保留。
- 剧情记录第一版：手动收录已读原文、阅读位置、书签、分支与回档；重启后恢复。共读问答使用当前路线范围内的原文与讨论，可点开原文依据。
- Hook 自动取词第一版：在小窗选择游戏进程与正文来源，预览确认后自动记录新台词；支持暂停、断开、手动 Hook 码、连续重复过滤与逐字增长合并。回档或切换共读会暂停记录。
- 当前路线会整理场景摘录和人物说辞：人物原话与旁白提及分开，回档后只保留这条线已读范围内的内容，整理本身不调用模型。建立共读时可选 Galgame 或小说。小说按章节切开，认识“某某说道”，未读章节不会进入提问。跨周目记忆和自动识别游戏存档尚未实现。
- 记忆管理：查看各次共读的原文、路线、书签、全部旧讨论数量和本机占用；可清空讨论、删除某次共读、找回或删除普通聊天，以及本机备份、恢复副本、删除备份和整理数据库空闲空间。清理会先预览范围，再明确确认。
- 接着上次读：原文页提供带原句入口的阅读回顾和最近聊过的问题；疑问、猜测和感受可以保留为共读手记，支持关联原文、修改、标记聊清楚及删除。手记随进度和分支使用，重启后保留，并进入后续共读提问。
- 故事脉络：剧情记录中的“脉络”将已读片段、人物说辞、选项、章节和玩家手记排成卡片，可按原文说话者、类型或关键词找线索，打开完整原句、留下关联想法或准备讨论草稿。回档、切线、备份和清理沿用已有记忆；整理和浏览不调用模型。
- 人物与称呼：核对原文后，明确告诉 Yuki“班长是美咲的称呼”或“这句讨论中的她指美咲”。支持修改、回档版本及删除全部版本；原文不改写，单句指代在推进后失效。
- 首次使用引导、独立的自编体验剧情，以及取词失败后直接粘贴的入口。缺少模型时使用原创纸签界面，聊天和记忆仍可使用。已加入不含私人素材的 Windows 免安装测试包构建，真实玩家安装和留存验证尚未完成。

## 本地准备

1. 源码版准备 Python 3.12+、Node.js 和 `requirements.txt` 依赖。可双击 `setup_yuki.cmd` 准备项目内 `.venv` 并构建，之后用 `start_yuki.cmd` 启动；也可用自己已准备好的 Python 直接运行 `start_yuki.py`。启动不再限定开发机路径，命令脚本也支持 `YUKI_PYTHON` 指定解释器。
2. 可选：将自行持有的模型运行文件放到 `app/public/model/`，入口为 `yuki_cutout.model3.json`；将合法取得的 Cubism Core 放到 `app/public/vendor/live2d-core/live2dcubismcore.js`。这些目录不会进入 Git。缺少素材或初始化失败时使用纸签界面，不影响文字共读。
3. 在 `app/` 执行 `npm ci --ignore-scripts`、`npm run check`、`npm run build`。
4. 正常启动后，鼠标移到模型上，在浮现的设置中填写接口。也可先复制 `.env.example` 为 `.env.local` 填写文字服务参数。
5. 使用已配置的 Python 运行 `start_yuki.py`；`--mode preview` 不调用云 API，`--headless` 只启动本机预览服务。默认监听 `127.0.0.1:12393`。

首次打开且未配置聊天、没有共读时显示使用引导；也可从气泡“··· → 使用引导”重新打开。可以先阅读并保存三句自编故事，再配置聊天。保存配置、整理原文和准备问题均不自动调用接口，测试与发送由玩家点击。引导中的“粘贴我的剧情”会新建游戏共读，避免把游戏混入体验故事。

收录一段剧情后，打开“剧情记录 → 脉络”即可查看故事卡片。“记个想法”把疑问、猜测或感受保存在共读手记中；可修改、标记聊清楚或确认删除全部版本。“一起聊”只填草稿，点击发送后才调用你配置的聊天服务。卡片连线表示阅读先后，不能当成故事中的真实时间或因果；选项节点不代表已经选择某个结果，人物说辞和玩家猜测也不会被升级成事实。筛选按原文说话者匹配，不自动合并别名或推断人物出场。

`python start_yuki.py --check` 只检查运行条件，不写阅读记录。`--data-dir 目录` 可独立保存配置与记忆。源码版默认沿用仓库旁的本机资料；打包版默认使用 `%LOCALAPPDATA%/YukiAI`，更新程序不清空记录。资料都不会进入Git。

## Windows 免安装测试包

本阶段提供本机构建和验收方式，尚未公开正式 Release。使用 Python 3.12 在独立构建环境安装 `requirements-build.txt`，前端先准备 `app/node_modules`，再运行：

```text
python -m scripts.build_alpha
```

产物位于被 Git 排除的 `artifacts/alpha-编号/`：解压整个 `YukiAI-Windows-Alpha.zip`，双击其中的 `YukiAI.exe`。包内已包含 Python、Qt和界面，不需要另装Python或Node.js。专用构建不读取 `app/public`，使用原创纸签图形，不含Live2D代码块、Core运行库、私人素材、密钥、阅读资料或取词二进制工具；可先用粘贴体验。包内附起步说明、依赖版本与许可证文件，并扫描本机已配置密钥。

这是本机Alpha验证路径，不代表已经在干净Windows虚拟机或真实新玩家中完成验收。完整阶段、待验证指标和下一步任务见 [产品成熟化路线](docs/PRODUCT_ROADMAP.md)。

Qt5的组件路径采用系统兼容名称处理中文解压目录；若目录名或所在磁盘无法提供纯英文兼容路径，启动提示会引导改用英文目录，例如 `C:\YukiAI`。全中文开头的目录也可能遇到此限制，个人记录的位置不受影响。

设置分为外观、聊天接口和语音接口。聊天填写 Base URL、API Key、模型完整名称；支持本机 HTTP 服务，外部服务使用 HTTPS。不支持 JSON 格式选项的服务可取消“请求 JSON 格式回复”。

Fish Audio 填写完整 `/v1/tts` 地址、密钥、模型及可选音色ID，默认 `s2.1-pro-free`，不自动切换模型。OpenAI 兼容语音填写 Base URL（通常以 `/v1` 结尾）、密钥、语音模型及音色名，程序会追加 `/audio/speech`。当前要求服务返回 WAV 音频。

“保存设置”只保存在本机，不调用云服务。“保存并测试聊天”会发送一句问候，“保存并试听”会发送一段固定试听文字；开启自动朗读后，正常聊天回复还会调用所选语音服务。语音失败时保留文字，回复超过1200字时仅显示文字，不自动截断朗读。

新设置优先保存在被 Git 排除的 `.yuki.local.json`，首次启动可读取原 `.env.local` 中的配置。两种语音服务的密钥分别保存；界面不会读取已存密钥，留空保留，勾选清除后再保存可删除。密钥仅由本机后端使用，不进入浏览器存储。配置文件是本机明文文件，请勿分享或提交它们。应用不自动发送模型或桌面素材。

## 一起读剧情

1. 鼠标移到模型上，点上方浮现的“剧情记录”图标，选“新共读”，填写游戏名称。每一篇共读都独立保存，适合区分不同游戏与周目。
2. 在“收录”中粘贴已经读过的中文原文，每行记录为一段；可用“美咲：台词”“旁白：描述”或选项形式。勾选已读再收录，单次最多200行、60000字，单行最多2000字。收录不调用模型，合法重复台词会保留。
3. 关闭记录面板，点“聊聊”输入消息。Yuki 带着正在读的这场末尾；这场中间如果被问到，也会打开那几句和前后文。更早的场次同样只打开对得上的句子。一场很长时，不会把整场无关句子送进模型；没打开的场次只留一句目录。超长的单句只把问到的那一段交给模型，本机仍保存全文。“原文”页的“目前记得”标出正在读的这场。“依据”可查看引用的原句。依据不足的回复会标明没把握。
4. 遇到选项先在“书签与路线”留书签。游戏读档后手动恢复相应书签；之后收录不同内容会自动另存为分支。也可主动新建分支，或点某条原文的“读到这里”校准进度。切换路线会前往该路线已记录的末尾。

回档或换路线会切换讨论范围，停止当前回复与朗读。原路线仍然保留。共读中的“新聊”会开始另一段讨论，旧讨论仍保留在磁盘；选择“普通聊天”则使用原有的独立聊天记录，不使用共读原文。

原文与共读讨论保存在被 Git 排除的 `data/story.sqlite3`，不自动导出或上传。提问时，送进聊天服务的是一小段打开的原文、未打开场次的短目录、人物索引和最近几句讨论，并且有总长度限制。这不代表模型看见了全部已读剧情。引用编号经过校验，而且只能来自这次打开的句子。回答里如果出现材料中没有的结局、真实身份或选项后果，会改写成不确定，并不再当作剧情判断保存。停在选项上时，只讨论态度，不讨论后果。编号有效或句子被保留，都不能证明每个推断都正确；模型仍可能误解台词，热门作品也可能用训练记忆换一种说法漏出后续。不能保证绝对无剧透。

## 本机记忆管理

入口：“剧情记录 → 记忆管理”。各次共读分别列出所有路线的原文、书签和讨论数量，讨论数量包含“新聊”以前的旧记录。占用分为共读数据库（含日志文件）、普通聊天和本机备份。

- “备份全部记忆”生成版本化的本机快照，包含全部共读、路线、进度、原文、讨论、手记、人物纠正、书签和普通聊天，放在被 Git 排除的 `data/memory_backups/`。不包含模型、接口配置、密钥和取词工具。备份是明文个人阅读资料，请自行保管。
- “恢复副本”校验文件摘要、结构、路线和原文依据后，给全部记录重新分配编号，恢复为独立副本。现有记录保留；正在读的副本恢复到备份时的位置。普通聊天副本可在同页“继续聊”。不支持把任意外部文件上传到恢复接口。
- “清空讨论”删除所选共读所有路线、所有旧讨论，原文、书签、路线和进度保留。“删除共读”同时删除该次共读的原文、路线、书签、导入记录、进度核对和讨论，其他共读保留。
- 删除、恢复均先预览范围，再勾选确认；预览五分钟过期，记录改变后需重新预览。影响阅读的操作会取消未完成回复和朗读、暂停取词并丢弃未保存缓冲。
- 已有备份独立保留，可用“删除备份”单独删除。系统不自动清理旧记录，没有回收站；需要保留恢复能力时先备份。“整理空间”回收数据库空闲页，保留现有内容；它不承诺磁盘安全擦除。

场景摘录、人物卡仍从有效原文重算。阅读回顾有本机持久缓存，删除共读时一并清理；恢复备份时会重建。自动生成的长期语义摘要、人物关系记忆和玩家偏好记忆尚未实现。

## 接着上次读与共读手记

入口：“剧情记录 → 原文 → 接着上次读 / 共读手记”。平时收起，不增加浮动窗口，也不自动覆盖对话气泡。

- 回顾展示当前进度内的几句原文摘录，以及这段讨论里最近三个问题。人物说辞标为“某某说过”，可点“看原句”。这是可核对的摘录，不额外调用模型生成长摘要。
- 点“留作疑问”保留一个讨论话题，或手动写疑问、猜测和感受，最多800字；可关联当前原文。“已聊清楚”是个人标记，不代表猜测被剧情证实。
- 在较晚阅读位置修改手记，会保留较早位置可见的旧版本。回到更早进度时，较晚的手记和回顾不会进入对话。分支也固定继承建立当时的父路线手记和讨论，父路线后来在同一位置写的新想法不会混进子路线。
- 后续提问最多带入四条相关手记，每条约200字，始终标为玩家想法；只有实际打开的原文编号可以作为剧情依据。修改手记会停止未完成的旧回复和朗读，自动取词继续运行。
- “新聊”保留已明确留下的手记；“清空讨论”保留原文、手记和书签；“删除共读”一并清理。单条手记的删除需要再点一次确认，会删除各路线中的所有版本，原文和讨论保留。
- 本机备份现为v3，包含手记、人物纠正的版本和关联依据，恢复时重新分配编号；兼容原有v1、v2备份。旧版路线没有可靠的讨论建立时间边界，升级后保守地隐藏子路线继承的旧父路线讨论，原记录仍在原路线及数据库中。

## 人物与称呼

入口：“剧情记录 → 原文 → 人物与称呼”，平时折叠。点“纠正人物对应”，选择称呼或单句指代，填写已读原文中出现过的人物；核对显示的原句并勾选后保存。整理和保存不调用云接口。

- 称呼对应从当前位置起随路线保留，之后讨论会把这个称呼说过的话归到目标人物下，原始说话者和台词保留。“玩家核对的称呼”只帮助认人，不能证明隐藏身份或关系猜测。
- “这句的她/他”只影响当前原文位置的讨论，推进后不沿用；以后明确问“第3句里的她”，仍可使用第3句的纠正。它不会把后续所有“她”都指向同一个人物。
- 修改只更换目标人物，先核对再保存；较早进度仍使用当时版本。分支固定继承建立时已存在的纠正，父路线后来补写的版本不会进入子路线。
- 每条纠正可查看关联原文，删除需再点一次，会删除各路线中这条纠正的全部版本。“新聊”和“清空讨论”保留人物纠正，“删除共读”一并清理；本机备份可恢复。
- 修改或删除后，未完成的旧回复与朗读会收起，自动取词继续。没有明确纠正时仍按原有规则推测，可能认错，需要玩家核对；不自动发现所有别名、隐藏身份或人物关系。

## 自动取词（Windows 第一版）

使用 [Textractor 官方项目](https://github.com/Artikash/Textractor) 的独立 CLI 进程注入用户选择的游戏。Yuki 不复制其引擎代码，也不把取词工具上传到仓库。当前固定使用官方 5.2.0 便携版，安装脚本核对 SHA256，仅取出 x86/x64 CLI、注入 DLL 及所需运行库，放在被 Git 排除的 `tools/textractor/`。

首次准备工具：用本项目 Python 运行 `python scripts/install_textractor.py`。此操作只下载并准备工具，不连接游戏。之后按下面的顺序使用：

1. 启动游戏，在“剧情记录”选择或新建对应游戏、周目的共读，然后打开“自动取词”。
2. 刷新列表，选择游戏窗口，点“连接游戏”。程序按进程位数选择取词内核；没有自动附加、提权或 Hook 搜索。
3. 在游戏中推进一句台词。逐个预览“正文来源”，找到与正在显示的正文一致的那一个，点“使用这个来源”。菜单、姓名单独出现的来源不要混入正文。整行就是「保存」「读取」「F5」这类界面文字时不会写入。自动识别 `姓名：台词`、`【姓名】台词`；姓名与正文分开时，可手动指定人物或暂时留空。
4. 确认上面选的是当前游戏的共读，勾选确认后点“开始记录”。只记录开始后新出现的文本，预览中的旧句不会自动补入。取词不会自动向 LLM 提问或合成语音。
5. 记录中会保存原始句子、整理后的正文与来源标识，过滤约1.5秒内连续重复输出，合并短时间内逐字增长的前缀。不同台词之间的正常重复会保留。点“暂停”立即丢弃未稳定的缓冲，后续仅预览。
6. 游戏读档前先暂停，在“书签与路线”恢复对应位置，确认来源后重新开始。Yuki 内切换共读、阅读位置、书签或路线会立即暂停并丢弃旧缓冲；在回退位置记录新剧情会另存分支。游戏或取词进程退出、来源过多、缓冲溢出等情况也会暂停。关闭 Yuki 会断开；下次启动不自动恢复连接。

“手动 Hook 码”可添加已知的 H/R 码，不含空格或换行，最多440个 ASCII 字符。这里不提供自动内存搜索。若来源为空或乱码，先核对来源、引擎与汉化版本；旧版内核的部分通用绘制 Hook、ANSI 编码或汉化补丁可能需要专用 Hook 码。第一版不保证支持所有游戏，也不能自动判断游戏是否已经读档；选项如何对应路线仍由玩家留书签和校准。

## 检查

```text
python -m unittest scripts.test_window_backend scripts.test_window_settings scripts.test_story_memory scripts.test_capture scripts.test_memory_management scripts.test_continuity scripts.test_characters scripts.test_delivery
python scripts/audit_upload.py
```

`scripts/verify_window.cjs` 需要本机另行准备模型、构建界面并启动预览服务，默认地址为 `http://127.0.0.1:12395/`，也可通过 `YUKI_VERIFY_URL` 指定。测试回复使用本地替身，不发送真实聊天请求。

`scripts/test_story_memory.py` 使用自编故事验证100句收录、重复提交、重启、回档、嵌套分支、请求取消、语音过期、只打开对得上的前后文、截断超长台词，并保持无关场次关闭、人物说辞和旁白分离、越界剧透降级，以及实际模型请求的上下文范围。`scripts/verify_story.cjs` 检查完整收录、书签、问答依据及小窗交互；它需在12396端口启动注入 `StoryFixture` 的独立本机服务，使用单独的缓存数据库和 `ConfigStore(..., env={})`，不要指向真实用户数据或服务配置。

`scripts/test_capture.py` 验证 CLI 文本帧、逐字增长、多行原文、重复过滤、过期缓冲、回档与跨游戏隔离、Hook 码校验和关闭清理。`scripts/verify_capture_native.py` 在 Windows 启动自己的屏外 GDI 样例窗口，真实注入官方 x64 内核，验证中文台词进入 SQLite、暂停不保存、断开不关闭游戏；只操作它自己创建的样例。`scripts/verify_capture.cjs` 在280×380小窗验证完整取词流程，使用12397端口注入 `RollingCaptureFixtureRuntime` 的独立服务、隔离数据和 `allow_cloud=False`。它不代替具体游戏的兼容性实测。

`scripts/test_memory_management.py` 验证旧讨论计数、跨共读清理隔离、预览失效、损坏备份拒绝恢复、恢复副本与引用重编号、异常回滚、重启、取消迟到回复和清理时暂停取词。`node scripts/verify_memory.cjs` 自行启动随机本机端口的隔离服务，在280×380和320×460中验证备份、取消/确认、清理、恢复、重启、普通聊天找回及删除；不读取真实记忆或服务配置，不调用云接口。

`scripts/test_continuity.py` 验证阅读回顾持久化、手记版本、回档与分支建立时的边界、模型材料标签与原文依据、分页、清理联动、v1迁移和备份恢复，以及修改手记取消旧回复但不中断取词。`node scripts/verify_continuity.cjs` 自行启动隔离服务，在最小窗口验证留疑问、编辑/标记、回档、重新打开、引用、文本转义、迟到回复、删除和备份恢复。全程使用自编文字，不调用云接口。

`scripts/test_characters.py` 验证称呼纠正、单句指代、修改版本、分支截止、原文保留、分页、备份兼容和取消旧回复；`node scripts/verify_characters.cjs` 自启隔离服务，检查小窗中的核对、勾选、修改、回档、重新打开、删除、迟到回复及恢复。使用自编文字，不调用云接口。

`scripts/test_delivery.py` 检查源码与打包的数据位置、指定目录、只读检查、无模型下的共读和打包排除规则。构建后设置 `YUKI_ALPHA_EXE` 为实际可执行文件，再运行 `node scripts/verify_delivery.cjs`：清除开发环境路径，使用独立资料目录和仅本机的聊天替身，验证首次引导、纸签操作栏、粘贴退路、保存不调用模型、明确测试/发送、原文依据及重新打开。不会读取真实记忆或调用云服务。

上传规则采用源码白名单；提交前仍需运行检查。模型和本地资料的缺失是有意安排。
